# Перевірка готовності до випуску

## Висновок

Основні функції пройшли автоматичні та серверні перевірки. Це не підтвердження
відсутності всіх багів і не повний аудит безпеки. Відкритий виробничий випуск
поки не рекомендований через HTTP без шифрування, старі некоректні дати та
незавершену візуальну перевірку. Для контрольованого тестування система доступна.

## Автоматичні перевірки

- 264 тести пройшли; два попередження про застарілий спосіб передачі cookies у тестовому клієнті.
- Перевірки форми профілю та каталогу спеціальностей у JavaScript пройшли.
- Перевірка покриття перекладів шаблонів пройшла.
- Перевірка синтаксису Python і форматування змін пройшла.
- Перевірено хешування, доступ адміністратора, повідомлення, опитування,
  події, рекомендації, QR-коди, Telegram-команди, підписки й імпорт профілів.
- Це локальні ізольовані тести, а не підтвердження доставки реальних листів чи повідомлень.

## Виправлення під час перевірки

1. Перезапуск більше не робить приховані профілі публічними.
2. Завершення події має бути після початку; дедлайн реєстрації не може бути пізніше початку.
3. Порожній початок події та нульова або від'ємна місткість відхиляються.
4. Час із часовим поясом нормалізується в UTC перед порівнянням.
5. Прибрані змішані українсько-англійські підписи класифікацій спеціальностей адміністратора.
6. Студент автоматично стає випускником, якщо коректний рік випуску менший за поточний.
   Перехід перевіряється при збереженні профілю, вході, захищеному запиті та запуску сервера.
   Поточний рік, майбутній рік, порожні та некоректні дати не запускають перехід.
   Професійний статус, інші ролі й адміністративні права не змінюються.

## Перевірки на сервері

- Головна, події, новини, профілі, ментори, реєстрація та вхід: HTTP 200.
- Адміністративні сторінки недоступні без входу: HTTP 401.
- Технічний користувач успішно увійшов; адміністративні дії відхилені: HTTP 403.
- Особистий профіль, повідомлення, налаштування Telegram та обидва API рекомендацій: HTTP 200.
- П'ять некоректних наборів дат відхилені: HTTP 400; профіль не перезаписаний.
- QR-код повертається авторизованому користувачу як PNG; анонімному доступ заборонений.
- База SQLite: integrity_check = ok; порушень зовнішніх ключів немає.
- У всіх наявних користувачів пароль у форматі PBKDF2-SHA256, не відкритий текст.
- Резервна копія створена та відновлена в окрему тимчасову базу, цілісність перевірена.
- Telegram має connected та актуальний службовий сигнал.
- Перевірені основні файли збігаються із локальною версією за контрольними сумами.
- Реальні листи, розсилки, повідомлення, реєстрації на події та опитування не надсилалися.

## Невирішене та межі перевірки

- У базі знайдено чотири профілі зі старими помилковими датами. Очищення очікує дозволу власниці;
  правильні значення не вигадуються, профілі не видаляються.
- Сайт доступний через HTTP; cookies мають HttpOnly, але не Secure.
  Не вводьте реальні виробничі паролі через незашифроване з'єднання.
- Браузерний інструмент не зміг запуститися: свіжі візуальні тести мобільного й настільного
  інтерфейсу, календаря, меню та перемикання мови залишаються непідтвердженими.
- Повний ручний цикл Telegram з реального клієнта та фактична доставка SMTP не перевірені.
- Новий JMeter-прогін, велике навантаження, сканування залежностей і тест на проникнення не виконувалися.
- Захист від перебору паролів і повнота CSRF-захисту всіх операцій потребують окремої перевірки;
  успішні функціональні тести цього не гарантують.
- Перевірка відсутності Telegram-токенів у поточних відстежуваних файлах є вузькою перевіркою,
  не повним скануванням секретів чи історії Git.
- Зміни розгорнуті на сервері; поточний запит не включав публікацію нових комітів у GitHub.
